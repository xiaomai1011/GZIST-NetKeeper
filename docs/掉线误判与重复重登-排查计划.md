## 一、三态的证据标准

| 状态 | 判定证据 | 不能推出什么 |
|---|---|---|
| **在线** | 受约束的外网 HTTPS 探测成功（现约束：仅 https、同 host、`resp.TLS != nil`、拒绝跳其它 host/明文，`portal.go:285-336`） | 推不出「刚才那组认证参数有效」 |
| **明确未认证** | 确认被重定向到**可信校园门户**，且门户地址/参数可核（`PortalInfo` 的 hijack 证据：ACIP、UserIP、UserMAC 来自可信 host，`portal.go:439-470`） | 推不出「密码错」 |
| **未知** | 超时、DNS/TLS 错误、连接失败、无可识别响应 | **不得据此提交密码** |

**铁律：连续 N 次「未知」仍然是「未知」，不会因为次数多而变成「未认证」。**

「未知」的允许动作：显示「网络异常」、**低频复核**（只探测，不提交）。复核间隔、连续确认次数、总预算
必须一起设计（见 §三·4），不能单独拍一个数字。

## 二、两个维度必须分开维护

v1 写的「Unknown 不清退避」不成立：那会造成「已联网仍报失败」或「网络一抖就重新提交」。改为：

- **网络状态** `netState ∈ {Online, Unauthenticated, Unknown}` —— 只由探测/门户证据推动；驱动 UI 与日志。
- **提交状态** `submit ∈ {Idle, Cooling(until), Blocked(凭据/占用)}` —— 只由**实际提交的结果**推动。

约束：
- 「未知」不提交 ⇒ **不产生任何提交失败记录**；
- 「网络已恢复」⇒ 停止提交，但**不计成功、不记组合**；
- 提交冷却只反映提交历史，**不因为"已联网"就被清零**。

## 三、一期范围（建议；实施需另行授权）

目标一句话：**只有「明确未认证」才自动提交；「未知」一律先复核，不猜。**

1. **探测改三态**：`Online()` 的 bool 换成 `{Online, Unauthenticated, Unknown}` + 原因枚举。
   **保留现有 4 秒超时、保留"两站任一成功即在线"**（不调参）。
2. **自动提交的触发条件收紧**：keeper 仅在 `netState == Unauthenticated` 时自动登录；`Unknown` 只低频复核。
   **手动「立即登录」不受限**（用户显式动作）。
3. **`Login` 内部加守卫**：自动路径在「未探测到门户劫持」时**不再继续提交**（现状会继续走 ACSetting 循环），
   直接返回「未确认未认证，未提交」。
4. **未知的低频复核**：候选参数 `recheck=30s`、连续确认 2 次，**但必须与探测超时、总预算一起核算最坏耗时**后定案；
   复核期间提交次数必须为 0。
5. **修 `remember` 的证据归属（提前到一期）**：现状 `portal.go:834-836` 在「Unknown + 探测通」时也
   `remember(sess)`，把没确认的组合记成「上次成功组合」⇒ 下次排到最前（`combos` 724-736）。
   改为**只有 `Classify == Success` 才记忆**。
6. **日志三句式**：`认证成功（门户确认）` / `网络已恢复，认证未确认` / `认证未完成：<枚举原因>`。
   不再出现「AC999 之后写登录成功」。
7. **提交冷却只由提交结果驱动**：BadCredential/InUse → 暂停；其它失败 → 退避；「未确认但网络恢复」只清异常显示。

**一期明确不做**：不改 4s/10s/退避序列任何时间参数；不动组合数量与 AC 回退；不改 UI 布局。

## 四、一期离线测试清单（**验收清单，尚未执行**）

复审指定 6 条：

1. 连续探测超时 → **不触发任何认证提交**（提交计数 = 0），状态 Unknown；
2. 一站失败、另一站成功 → 判在线，不提交；
3. 明确门户拦截（hijack 证据成立）→ 正常进入认证流程；
4. `AC999` 后外网恢复 → 停止提交、**不记忆组合**、日志为「网络已恢复，认证未确认」、**不出现「认证成功」**；
5. 取消 / 总预算到期 → 全流程可终止，无残留 goroutine、无迟到提交；
6. 正常登录路径不回归（成功 / 密码错误 / 已在线 / 参数不匹配各一例）。

补充 3 条守卫：

7. 连续 5 轮未知 → 提交计数仍为 0，只有复核；
8. 「未确认 + 探测通」之后，`LastSession` **不被污染**（首选组合不变）；
9. 已在线时不得出现任何「登录失败」类文案（状态分离回归）。

**补验收边界后的新增用例（10–16）**：

10. **伪门户**：最终跳到酒店/热点门户（非白名单主机、无 `wlan*` 参数）→ 判**未知**，不得判未认证、不得提交；
11. **参数与网卡不符**：劫持页的 `wlanuserip`/`wlanusermac` 与本机网卡不一致 → 证据作废 → 判未知；
12. **跨网络环境**：更换网络后（网卡 IP 变化）→ `LastSession` 的 AC/IP/MAC 不得被当作证据或排序依据；
13. **手动入口**：未知状态下手动点击 → 允许提交，但日志/界面必须写明「网络状态未知，按用户要求强制尝试」；
14. **凭据阻断不可绕过**：`PausedByServer(BadCredential)` 下手动点击**不得静默清除**暂停（只有账号变更或二次确认可解除）；
15. **取消对两种入口同等生效**：自动/手动提交途中取消，都必须在有界时间内返回且不再继续提交；
16. **展示分离**：网络在线但上次认证失败 → 显示「网络可用；本次认证未确认」，且**不出现**「离线」「正在重登」。

**v2.2 新增（17–22，门户入口与入口语义）**：

## 七、对 v1 三处过强表述的更正

1. **「最多 16~20 次提交」** → 是 `2(suffixed) × N(AC) × 2(MAC)` 的**组合上界推导**，不是实测提交次数；
   实际每轮会被「参数不匹配继续 / 其它结果短路」影响。改为：**组合上界 16~20，实测未做**。
2. **「固定 10 秒一轮的风暴」** → `Interval=10s` 只是重试**等待**；整轮实际耗时 = 探测（最多 2×4s）
   + 提交（每组合最多 10s）+ 等待 2s + 复核，**未实测**。改为：**重试等待 10s、整轮耗时未测**。
3. **「真掉线晚 4 秒发现」** → 未测。4s→8s 的实际影响取决于两站串行/并行、连续确认次数与监控间隔。
   **一期不动该参数**，需要时先测最坏耗时。

## 九、三条验收边界（实施前必须写死的合同）

### 9.1 可信门户证据：**两个白名单必须分开**（v2.2 修正）

**v2.1 的错**：只允许 `/eportal/` 或根路径含 `c=ACSetting`，会把**真实出现过的正常入口**判成未知。
用户提供的真实地址是：

```text
http://10.0.10.252/a79.htm?wlanusermac=…&wlanuserip=…&wlanacip=…     ← 端口 80，不是 801
```

**A. 门户发现入口**（回答"是否需要认证"，`PortalInfo` 用）

| 已确认组合（协议+主机+端口+路径整体匹配） | 依据 |
|---|---|
| `http://10.0.10.252/a79.htm?wlanusermac&wlanuserip&wlanacip` | **用户提供的真实访问地址，必须支持**；该样本里的 `wlanacip` 是 **`10.128.255.144`** |
| `http://10.0.10.252/`（可带 `c=ACSetting` 等门户参数） | 现网观察（`discoverAC` 走这个）——**仅用于发现参数，见 9.1.2** |

**B. 认证提交端点**（真正提交密码的地方，`Login` 用）

- `http://10.0.10.252:801/eportal/`，查询串含 `c=ACSetting&a=Login`（与现网日志一致）；
- 提交端点**不用于**判断是否需要认证；发现入口**不用于**提交。

**C. 匹配方式**：协议 + 主机 + 端口 + 路径按**已确认组合整体匹配**，不得"分别允许后任意拼接"：
`http://10.0.10.252:80/eportal/`、`http://其他主机/a79.htm`、`https://10.0.10.252/a79.htm`（未观察过）
**都不算**已确认入口。

### 9.1.1 参数：缺失 / 冲突 / AC 证据强度（v2.3 修正）

| 情形 | 判定 | 处理 |
|---|---|---|
| **必要参数缺失**（IP / MAC / AC 任一） | **未知** | 不提交；**不得用 `LastSession` 补齐后当新鲜证据** |
| **参数存在但与当前选定网卡冲突**（IP 或 MAC 不符） | **证据无效** | 判未知，不提交 |
| `wlanacip` 来自**本次**重定向参数 | 可作为证据的一部分 | 与 IP/MAC 一并构成新鲜证据；**不要求它属于某个"已验证白名单"** |
| `wlanacip` 只出现在配置/旧会话里 | 证据不足 | 判未知；只能参与排序 |
| **网络身份变化**（网卡 IP / MAC / 门户主机变了） | 旧会话作废 | `LastSession` 既不参与请求，**也不参与排序** |

**AC 证据分四档记录，不要混成一份"已确认列表"：**

| 档位 | 地址 | 依据 |
|---|---|---|
| **真实样本中出现过** | `10.128.255.144` | **用户提供的真实门户地址里就有**（`wlanacip=10%2E128%2E255%2E144` 解码）⇒ 不是"仅配置遗留" |
| 发现记录 + 明确认证成功 | `10.128.255.143` | 证据最强（有发现记录，也有 `Login succeed`） |
| **请求中出现、未验证有效** | `10.128.255.142`、`10.128.255.129` | `.142`：日志出现过，同批返回 Portal 超时；`.129`：**日志里有 38 次 ACSetting 提交**（10-10 起，最近 10-21 15:45），抽样最近 4 次全部返回 `Portal协议认证超时` ⇒ **"出现在参数里"≠"已验证有效"，但它确实被用过，不属于"仅配置候选"** |
| 仅配置候选（未见过使用） | —— | 目前没有；将来若出现只写在 `DefaultACIPs`、日志里从未提交过的地址，才归此档 |

**关键**：能不能用 `/a79.htm` 判"未认证"，**不取决于 AC 是否在某个窄白名单里**——否则会拿真实样本
（`.144`）把自己的正常入口拦掉。判据是"**本次新鲜证据 + 本机参数匹配**"，AC 只作为参数完整性的一部分与排序依据。
`.144` 也不因此对所有网络都适用：仍然要求它是**本次**重定向里拿到的。

### 9.1.3 不设窄白名单 ≠ 接受任意 AC 字符串（v2.4 新增，实现边界）

| 校验 | 要求 |
|---|---|
| 格式 | 必须是**合法 IPv4**（沿用 `validIPv4`，拒绝域名、IPv6、带端口、带前缀的字符串） |
| 重复 / 冲突 | 同一请求里出现多个同名参数或 `wlan_ac_ip` 与 `wlanacip` 冲突 → **判未知，不提交** |
| 作用范围 | AC **只能作为参数**发给**固定认证端点** `http://10.0.10.252:801/eportal/`；**不得**用它拼接 host / 端口 / 路径，也不得据此改变请求目标 |
| 来源 | 只接受**本次重定向参数**里的 AC 作为新鲜证据；配置与旧会话里的 AC 只能参与排序 |

### 9.1.2 证据来源：门户根地址可访问 ≠ 被拦截 ≠ 未认证（v2.3 新增）

- 直接 GET 校园门户根地址**成功**，**不构成**"被门户拦截"，也**不构成**"未认证"；
- 根路径只用于**发现参数**（`discoverAC` 的用途）；
- 判「明确未认证」必须同时记录两条来源：
  1. **本次外网探测确实被引向允许的门户**（例如访问外网站点后最终落在白名单门户，而不是我们自己主动请求根地址）；
  2. 该门户给出的参数是**新鲜的**，且 `wlanuserip` / `wlanusermac` 匹配**当前网卡**；
- **单纯从门户首页读到参数，不能触发自动提交。**

### 9.2 自动与手动入口的契约（v2.2 消除"点击＝二次确认"歧义）

原则：**一次普通点击只做一件事**，不能同时充当"强制尝试 + 解除凭据阻断 + 跳过冷却"。

| 维度 | 自动（Tick） | 手动（普通「登录」按钮） |
|---|---|---|
| 未知状态可提交？ | **禁止**（一期硬约束） | 允许，但**提交前**必须明确告知（按钮/提示写"网络状态未知，仍要尝试？"），**不是提交后补一行日志** |
| 取消（ctx） | 立即生效 | 同样立即生效 |
| 提交冷却 | 遵守 | **严格遵守，一期不提供覆盖**；冷却内点击只提示剩余时间 |
| 凭据错误阻断 | 遵守 | **不能直接解除**，按下面两条路径之一处理 |

**凭据阻断的解除（v2.3 修正：不再要求"变更 + 确认"同时满足）**

| 情形 | 处理 |
|---|---|
| **账号或密码任一实际变化** | **清除旧凭据的阻断**（旧阻断不该套到新凭据上），但**不因此自动提交**；下一次仍需满足网络状态/冷却守卫 |
| **凭据没有变化** | 必须由**单独、明确的「重试此凭据」确认**（独立按钮/确认框）才允许解除；普通「登录」按钮不算 |

两种情形**都继续遵守**冷却、取消与网络状态守卫。

**凭据指纹的实现约束**：指纹只用于判断"输入是否变化"，是**会话内**机制——
**不落盘、不写日志、不保存可用于离线猜测的普通密码哈希**；采用**带随机密钥的 HMAC**（密钥仅存内存，
进程退出即失效）。不能凭 `AccountChanged` 这个事件名推断"已经换过密码"，必须比对实际值。

**实现约束**：两条入口收敛到 `attempt(trigger)`；`trigger` 只决定"未知是否允许提交"，
其余守卫（取消、冷却、凭据阻断、单次提交）**共用同一份代码**，手动入口不得成为旁路。

### 9.3 展示分离（示例再收窄）

- **禁止**：当前网络已在线时显示「离线」，或持续显示「正在重登」；
- **必须保留**真实结论，且**不得暗示账号密码被拒**：
  - `网络可用；本次认证未确认`
  - `网络可用；本次认证接口返回失败（AC999），具体原因未知`
    ← 替换 v2.1 的"刚才认证被拒（AC999）"
- `网络` 与 `本次认证` 两个字段独立维护，UI 不得用一个覆盖另一个。
